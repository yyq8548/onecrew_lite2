# 客户安装的路径与版本约束

适用于 TypeScript 统一程序的 Windows 安装、升级和 Codex 插件连接。源码中的测试工作区路径不作为产品默认路径；账号和历史数据保持原归属。Mac ARM / Intel 原生验收未完成。

## 路径归属

| 位置 | 用途及核验 |
| --- | --- |
| 用户启动的程序 | 可以位于安装目录、下载目录或插件目录。读取当前程序的真实内容和稳定文件身份，不要求向该目录写资源。Windows 原生路径表示保留长路径支持。 |
| 明确指定的数据目录 | 保存原 Vault、账号、数据库、实例描述和端口。要求当前用户私有权限，拒绝重解析点和错误归属，不自动换成空目录。 |
| 数据目录内 `.windows-host/bin/<SHA-256>.exe` | 持久服务程序。当前程序按完整哈希保存，核验后复用，安装锁由操作系统管理。独立于临时安装文件，原文件移走不改变服务归属。 |
| 按用户划分的资源缓存 | 由内嵌 manifest 确定内容。权限、目录清单、逐文件大小与 SHA-256 均需通过；缓存损坏明确失败。 |
| Codex 插件目录 | 官方 ClientAdapter 安装并完整核验。插件哈希、服务实际哈希、Library 接口能力和结果回读共同决定验收结果。 |

Windows 桌面宿主可能将文件重定向到另一个物理位置，而目录的 `realpath` 仍返回逻辑位置。资源加载以经过稳定读取和内容核验的 `.complete` 文件确定物理根目录，再重新核验完整缓存。卡片仍执行严格路径及文件身份检查，不允许任意别名或缺失资源。

Windows 中的运行时可能截断超长自身路径。统一通过 QueryFullProcessImageName 查询当前进程的实际映像，并使用 Windows 原生路径表示。服务保存、构建哈希、插件准备和迁移指纹使用同一经过核验的路径，不使用 argv 或工作目录猜测位置。解析脚本属于内嵌 manifest 资源，执行前核对 SHA-256。

## 启动和升级

1. 核验明确的数据目录及现有 owner，不安装、不迁移用户账号来修复连接。
2. 已有服务必须与当前客户端的实际程序哈希相同。不同构建返回 `service.build_update_required`，保留旧服务，由安装流程明确停止和替换；不能只返回一个在线端口。
3. 当前程序稳定读取后写入私有哈希目录。独立安装锁串行化并发操作，文件按完整哈希核验，不覆盖不匹配的现存程序。
4. 计划任务以当前用户、最低权限、无自动触发器运行，绑定数据目录、程序、脚本、参数和哈希。正常停止仅移除本目录的任务；不按进程名称清理其他程序。
5. 独立宿主仅保存 LOCALAPPDATA、APPDATA、USERPROFILE、HOME 的物理路径及未设置状态，不把整个环境或秘密写入配置。
6. 启动后核对实际程序哈希和源 manifest、数据归属、Access、插件加载及 Library；宿主重启后重新回读状态卡、工作台与同一动态表格。

新安装的端口先由操作系统通过 loopback 的端口 0 分配，再保存到私有 profile。已有 profile 和经过验证的升级端口保持原值。分配监听关闭后，正式服务仍需成功绑定该端口；期间若被占用，启动明确失败，不改端口或掩盖故障。避免目录哈希选中 Windows 排除端口，也不修改系统的端口排除设置。

## Windows 验证

真实测试覆盖普通用户权限、中文和空格、超过 260 字符的安装路径、独立数据目录、原安装文件移走、并发安装、不同构建拒绝复用、明确停机后替换、原端口保留、父 Job 退出、资源缓存损坏及桌面宿主文件重定向。每项以实际测试日志为准，当前结果见 `28-sync-and-table-loading-windows.md` 和包内 `RELEASE-STATUS.md`，未通过或未完成不得记作成功。

客户正式交付还需完成最终配套包和宿主联合验收。11 项许可全文缺失仍是发布门槛，构建保持 `productionReady: false`。Mac 原生验收与 Windows 结果分开记录。安装复用用户日常 Chrome 的已授权身份，不创建独立浏览器。

## 开发清理约定

保留当前版本、上一版和仍被实际进程、计划任务、插件或验证引用的产物。更早且确认不用的本任务构建和缓存可在开发期间清理。清理必须使用同一文件系统接口，先核对解析后的绝对路径位于当前工作区；不跨入全局插件缓存或用户目录，不删除源码、账号数据、浏览器身份和必要验收日志。用户数据的迁移、归档和删除不属于此清理授权。
