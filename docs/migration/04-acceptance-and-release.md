# 迁移验收矩阵与发布执行要求

本表定义当前 TypeScript 独立版本的验收要求，执行范围受 08-current-scope.md 约束。实际结果见 14-handoff-status-and-next-plan.md 与 28-sync-and-table-loading-windows.md；没有实际证据的条目保持未完成。每项记录源码提交、包 SHA-256、OS/CPU、步骤、实际结果和执行日期；历史版本结果不能自动计作当前构建通过。

## 1. 执行规则

- 使用真实本地进程、真实数据库和授权测试账号。不新增 mock、伪造平台响应或编造搜索结果来满足验收。
- 不自动发送邮件、私信或发布内容；发送类检查必须获得对测试对象和内容的明确授权。
- 真实用户数据只在受控本机做副本，令牌、Cookie、密钥、正文和私人链接不进入Git。
- “通过/失败/阻塞/未执行”分别记录。没有设备或账号时为阻塞，不能写通过。
- 自动检查能执行的部分由开发者执行并修复；平台人工授权只在确实需要账号持有人操作时请求。
- 任何包内容变化会改变验收对象，必须重建并复验受影响范围。

## 6. 发布记录模板

每个候选创建独立记录，至少包含：

- 产品版本、修订、源码commit/tree、Node及锁文件身份。
- 每个目标的OS最低版本、ZIP对象key、字节数、SHA256、签名状态。
- 组件/原生扩展版本、插件兼容范围、数据库schema和迁移版本。
- 用例编号、结果、实际证据文件、测试账号范围和授权记录引用。
- 已知限制、未执行项、发布阻断或经用户明确接受的例外。
- GitHub/GitLab MR、Access提交、Worker版本、清单ETag和发布时间。
- 旧清单及对象、数据恢复点、回退命令入口、验证结果。

证据分两类保存：Git中只放脱敏摘要和构建身份；私有原始日志/数据库/私人链接在受保护环境保存并标明保管位置。不得为了可复现而把客户凭据提交到GitHub。
