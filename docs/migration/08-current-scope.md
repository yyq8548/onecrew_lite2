# 当前迁移范围

本文件记录用户对原迁移计划的明确调整，作为本开发分支的当前产品范围。来源基线为 GitHub `efc3c6eb69507b9809bb30279d9af26156d075e3`，开发分支为 `codex/typescript-unified-gmail`。

## 保留

- 各平台公开搜索、身份、资料、原帖、评论、群组及管理员读取，连同必要的认证、代理和会话。
- 发现计划、证据、评分、身份合并、预算、暂停恢复和同步恢复。
- Creator、联系途径、导入导出、分组、历史记录和非发送确认流程。
- Library 动态表格及统一程序内的表格同步；现有字段、记录和来源引用保持兼容。
- 当前邮件页的 GmailBulk，包含 Google OAuth、冻结草稿、确认、暂停、继续、取消、跨批去重和未知结果保护。
- 状态卡、工作台、Codex 接入、安装与更新生命周期。
- Access 登录验证码和系统邮件。

## 删除

- X Chat、Instagram 和 Telegram 私信发送与远端私信同步。
- 社交关注、取消关注、公开回复和通用社交发送审核。
- 通用社交触达的目标准备及关注关系检查；历史联系账号、会话、分类和发送回执继续保留。
- 单封邮件的用户撰写、回复及发送入口。
- MCP 的 Resend 用户批量发送、operator 配置及专用发送审核链。
- 上述操作的 HTTP、MCP、工具目录、目标动作、引导、展示、翻译和官网说明。

旧发送状态与回执保持可读，不删除用户数据。旧请求不能通过通用执行接口重新取得发送能力。

## 必要共享代码

GmailBulk 当前依赖内部 `send_manual_email`、发送前永久尝试标记、邮箱快照及回读提交。移除单封用户入口时，这些内部逻辑仍需保留或抽离为 GmailBulk 内部接口。

Creator 保存、搜索计划和选择仍使用共享确认与结果续接协议；仅删除社交及旧邮件发送用途。Telegram 群组读取需要原账号会话，公开平台读取也复用了诊断类型。

Teable 的全部导出能力不等于产品功能。当前 Library 仅创建 singleLineText、number、checkbox、date，限制 100 列。Calendar、Kanban、Gallery、Form、Button 工作流等不新增为产品入口；必要的表格内部依赖继续保留。

原 `creator-sync` 的生产配置已将 Creator 云快照上传标记为 `Retired`，在读取凭据、导出及上传前结束。迁移保留此停止边界，不恢复历史快照上传接口。该边界与仍需保留的 Access 配对、本地 Library 投影和动态表格同步分别处理。

## 原计划变更

- M01 删除 X Chat 密钥恢复验证；Chrome、X 只读网络和 Telegram 公共会话验证继续执行。
- M02 记录明确退役的操作及错误响应；保持其余合同和数据兼容。
- M06、M07、M09 只迁移保留能力和历史解码，不恢复旧发送执行链。
- M10 移除发送入口及专用确认展示，保留 GmailBulk 和非发送确认。
- M15 不发送真实邮件作未经授权的验收，不用模拟结果代替平台与数据库验证。

用户确认当前没有 Mac ARM、Mac Intel 设备或远程环境；继续源码实现和 Windows 验证，两种 Mac 的原生与安装验收保持未完成。Windows 验证不替代 Mac 验证。

Windows r3 来源缺口、公司当前 Access 源码及发布授权仍按原计划分别核实。
